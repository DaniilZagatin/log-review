# Этап: смысл мест логирования

Для каждого места логирования из `sites` определи, какую операцию карты оно наблюдает и какую роль играет запись в её жизненном цикле. Место найдено статическим поиском; его ключ и поля — кандидаты из текста вызова.

Для каждого места верни хотя бы один элемент `bindings`:

- `decision=bind` — запись наблюдает операцию из `candidate_operation_ids` этого места. Укажи `operation_id`, `event_role`, `lifecycle_moment`, `business_meaning` и `evidence`.
- `decision=no_operation` — запись техническая или диагностическая и не отражает бизнес-факт ни одной из операций-кандидатов. Объясни в `business_meaning` и сошлись на строку вызова.
- `decision=unresolved` — по выданным строкам смысл установить нельзя. Задай в `question` конкретный вопрос: что нужно прочитать или уточнить.

Роль записи (`event_role`):

- `request` — запрос действия или отправка во внешнюю систему; результат ещё не известен.
- `queued` — постановка в очередь.
- `start` — фактическое начало работы.
- `result` — получен или сохранён результат операции.
- `refusal` — отрицательный результат по бизнес-правилу.
- `error` — ошибка исполнения.
- `retry` — повтор технической попытки.
- `duplicate` — обнаружена повторная доставка или дубль.
- `cancellation` — отмена; `compensation` — компенсирующее действие.
- `state_change` — изменение состояния предмета процесса без завершения операции.
- `diagnostic` — служебная запись без бизнес-факта.
- `unknown` — роль не установлена.

Момент записи (`lifecycle_moment`): `before_action`, `after_action`, `before_commit`, `after_commit`, `on_response`, `on_failure`, `unknown`. Запись до сохранения не доказывает сохранённый результат; запись об отправке запроса не доказывает исполнение получателем.

`repeat_semantics`: `once_per_execution` — одна запись на выполнение операции; `per_attempt` — на каждую попытку; `per_delivery` — может повториться при повторной доставке; `unknown`.

`case_fields` — только имена из `fields` этого места, которые идентифицируют предмет процесса (заявку, договор, клиента и т. п.). Не добавляй имён, которых нет в `fields`.

`evidence` обязательно включает строки самого вызова логирования. Для вызова обёртки (`kind=wrapper_call`) сошлись и на строки обёртки, где она передаёт ключ и поля в запись; иначе выбери `unresolved`.

Одно место может наблюдать несколько операций только при различимых условиях. Тогда верни несколько элементов `bind` и в каждом заполни `condition` — когда запись относится к этой операции.
