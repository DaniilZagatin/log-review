# Карта → логирование операций

Новый основной маршрут принимает готовый результат первого агента. Его операции, ID, переходы, группировка, цитаты и ограничения сохраняются. Второй агент ищет существующие записи по тому же коду, интерпретирует их относительно операций и предлагает адресные изменения. Построение карты, технический GLM-обзор, сведение контекста и бизнес-метрики здесь не запускаются.

## Вход и команда

Требуется Python 3.11+, стандартная библиотека. Входной HTML и код приложения не выполняются. Первый агент и второй последовательно используют тот же каталог репозитория.

```bash
python3 -B run.py review-logging --map /path/to/scenario_map.json --repo /path/to/same-repo --inventory-only --out output/inventory-01
python3 -B run.py review-logging --map /path/to/scenario_map.json --repo /path/to/same-repo --config /path/to/profile.json --max-requests 128 --out output/logging-01
python3 -B run.py export-logging --run output/logging-01 --out output/export-01
```

На Windows: `py -3`. Профиль — либо конфигурация одной OpenAI-compatible модели, либо существующий объект с `business` и `code`. Используется только business, code не создаётся и не вызывается. Ключ задаётся через имя переменной окружения `api_key_env`; значений ключей в профиле нет. TLS/параметры провайдера обрабатывает прежний модельный адаптер. Эта реализация не пополняет бюджет и не меняет существующий учёт расходов. Внешняя обёртка учёта должна резервировать каждый физический вызов, если используется денежный ledger.

`--inventory-only` не создаёт модель и не читает профиль: все операции X, пока их смысловая привязка не проверена. Исключение — карта без операций, где запросов нет и процента нет. Input должен быть опубликованным `scenario_map.json` формата 2.0 со статусом completed/partial; checkpoint/running/failed отклоняются. Частичная исходная карта сохраняет свою область и ограничения.

Для единственного source-N префикс автоматически соответствует корню `--repo`. Если первый агент получил несколько каталогов внутри этой репозитории, передайте `--source-root source-1=service-a --source-root source-2=service-b`. Пути остаются относительными и не выходят за допущенные исходники. Используйте физические пути без символических ссылок; в macOS системный временный путь `/var/...` при необходимости приведите к `/private/var/...`.

## Повторное использование первого результата

Рядом с картой автоматически ищутся необязательные `map_hierarchy.json`, `code_context.json`, `read_fragments.jsonl`. Можно явно задать `--hierarchy` или `--artifacts`. Без них запуск работает. Несовместимая иерархия отключается с пояснением, операции не исчезают.

Новые sidecars первого агента содержат существующие статические находки, допущенный список файлов и реально прочитанные фрагменты. Это локальные подсказки для адресных пакетов, не новый снимок/протокол передачи исходников. Проверяются map_run_id и хеш маскированного текста; несовместимые материалы не переиспользуются. Пропуск/withheld означает отсутствие переданного текста, а не отсутствие кода или логов. Статистика экстрактора не считается покрытием операций.

## Как проходит анализ

1. Детерминированный поиск собирает полный реестр кандидатов без лимита 300/40/100. Его ограничения сохраняются. AST Python и эвристики других языков — навигация, не доказательство исполнения.
2. В модельный пакет попадает одна исходная операция с неизменным ожидаемым смыслом, её цитатами, относящимся кодом и кандидатами. Содержащие функции и прямой контекст читаются адресно. Модель может запросить read/search/who_calls или уточнение имён wrapper, не изменяя карту.
3. Код проверяет ID, место физической записи, реально выданные строки, цитаты, принадлежность invocation рассматриваемой операции и доступность существующих полей в месте изменения. Сходство ключа/строки не даёт готовой привязки. Общая запись требует основания конкретного вызова.
4. Модель интерпретирует роль и смысл: запрос, начало, результат, ответ получателя, ошибка, повтор, no-op. Собственная операция отказа может покрываться error-записью; та же запись не подтверждает новый успешный эффект другой операции. Отправка не означает применение у получателя. Проверенная цитата не доказывает правильность интерпретации.
5. Код считает состояния и процент, формирует отдельный слой рекомендаций. Предложения не повышают покрытие существующего кода.

Ограничения: для Java/Kotlin адресные цитаты и прямые записи проверяются, но разрешение цепочек вызовов пока ограничено. Неподдержанная навигация не позволяет заключить отсутствие записи: такой случай остаётся X. Для Python неоднозначная реализация получателя с возможным логированием также остаётся X. Нестандартные обёртки требуют подтверждения реализации или отдельного контракта именно логирования; обычный handler бизнес-сообщения не подходит. Неразрешённая обёртка, неполный существенный контекст или конфликт — X. Прямое поле ID не является обязательным для каждой операции: допустим достаточный контекст или проверяемая связь. Существующее выражение поля должно быть доступно в указанном участке; новый ключ/константа помечается как предлагаемая.

## Состояния и процент

- C — существующая запись устанавливает факт и существенный результат этой операции.
- P — подходящая запись есть, но минимальный сигнал покрыт не полностью; необходимый поиск завершён.
- U — после предусмотренного поиска подходящей записи не найдено в проверенном коде.
- X — проверка не закончена, существенный текст недоступен, есть конфликт или ошибка.

Знаменатель фиксирован: **N = C + P + U + X**, все атомарные операции входной карты. Группы не добавляют операции. При X=0 основной процент равен `100 × (P+U)/N`. При X>0 — диапазон `100 × (P+U)/N … 100 × (P+U+X)/N`. Нижняя отображаемая граница округляется вниз, верхняя вверх; при полном анализе одно округлённое число. При N=0 процента нет. Отдельный U/N не подменяет основной показатель.

Это покрытие операций **по коду**, не доказательство runtime-исполнения, включённого уровня, коммита или доставки. Полнота всего процесса/репозитория не выводится из полноты известной карты.

## Лимиты, прерывание и продолжение

`--max-requests` ограничивает смысловые запросы включая repair; CLI отдельно ограничивает тем же числом физические транспортные попытки, в том числе HTTP429. В результате они учитываются отдельно. Параметр не является денежным балансом. `--request-chars` проверяет полный пакет system+user, не обрезает текст. `--max-context-lines` и `--max-navigation-turns` ограничивают адресные уточнения; остаток остаётся X.

Один адресный repair на операцию. После реального неудачного repair разрешено исключение только вспомогательных guidance_ids и присланных моделью state/status/coverage/counts/percent/percentage с предупреждением; неверные operation/site IDs, источники и поля не принимаются. Transport/resource ошибки не превращаются в schema-repair. Подробности HTTP429 — в конфигурации прежнего адаптера; скрытого третьего семантического запроса нет.

После каждой операции атомарно сохраняется `logging_review.checkpoint.json`. При штатном завершении он входит в итоговый JSON и временный файл убирается только из нового принадлежащего запуску каталога. Прерывание во время модельного запроса сохраняет честный partial и все операции, оставляет непросмотренные X; CLI возвращает 130. При аварийном выходе принятый префикс остаётся в checkpoint. Для продолжения нужен новый output:

```bash
python3 -B run.py review-logging --map /path/to/scenario_map.json --repo /path/to/same-repo --config /path/to/profile.json --resume-from output/logging-01 --out output/logging-02
```

Сохранённый ответ повторно проверяется по точному пакету, карте, файлам, политике, промпту и полной конфигурации модельного запроса, включая reasoning effort; несовпадение — новый запрос в пределах разрешённого продолжения. Финальная сверка конфликтов повторяется по всем операциям. Контроль хешей — корректность локального кэша, не криптографическое доказательство происхождения ответа от провайдера.

## Результаты и приёмка

`logging_review.json` — главный результат. `report.html` — автономное представление с тремя разделами: Карта/Логирование/Доработки. Карта получает цвет покрытия и детальное раскрытие имеющихся групп; исходные связи сохраняются. Полный реестр технических и несопоставленных мест доступен отдельно. Прямые ссылки открывают текст кода, не выполняют его. `operations.csv`, `logging_changes.csv`, `SOURCE-ARTIFACTS.json` и `SHA256SUMS` обеспечивают переносимый экспорт. CSV защищён от формул. `export-logging` не читает репозиторию и не вызывает модель.

Проверки: `python3 -B scripts/test_offline.py --pattern 'test_map_first*.py'` и полный offline suite с синтетической конфигурацией. Контроллер отчёта проверяется Node при наличии; это тест с инертными DOM-заглушками, не визуальная браузерная проверка. Демо/recorded replies не являются живым E2E или доказательством бизнес-полноты. После реального разрешённого запуска нужно отдельно посмотреть смысл каждой существенной привязки, пригодность доработок и ограничения исходной карты.
