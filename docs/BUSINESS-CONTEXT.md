# Контекст бизнес-модели

По умолчанию `--business-request-chars 240000` ограничивает размер текста system+user. Это ограничение приложения, а не размер контекстного окна модели.

При наличии совместимого локального `tokenizer.json` можно включить дополнительную проверку:

```sh
python run.py analyze --repo /path/to/source --out /path/to/new-result \
  --config /path/to/model.json --business-request-chars 4000000 --digest-chars 180000 \
  --business-context-tokens 1000000 --business-tokenizer /path/to/tokenizer.json
```

Для этого режима нужна необязательная зависимость `pip install '.[tokens]'`. По умолчанию она не требуется. Приложение загружает только JSON-данные токенизатора, не скачивает файлы и не выполняет remote code. Токенизатор должен соответствовать выбранной модели; оператор отдельно проверяет ограничения модели и провайдеров.

Общий предел включает текст входа, максимальный ответ из конфигурации модели и 8 192 токена резерва на оформление chat-запроса. При 1 млн и ответе 131 072 остаётся 860 736 токенов текста. Это оценка локального токенизатора с резервом: фактический `usage.prompt_tokens` сообщает провайдер. Символьный предел действует одновременно как отдельный ограничитель памяти; увеличение только токенного предела не отменяет его.

Упаковщик также оставляет место для одного validation repair. Непосредственно перед каждой отправкой исходный или repair-запрос проверяется целиком. Текст не обрезается. Сведения о токенизаторе и пределах входят в идентичность бизнес-конфигурации и trace; технический кеш от этой настройки не меняется.

Полное бизнес-описание резервируется до кандидатов и областей кода. Если всё не помещается, уменьшается страница. Невручённые кандидаты переходят на следующие страницы или явно отмечаются deferred при достижении лимита запросов/непомещающемся отдельном кандидате. Наличие источника и допустимая форма ответа не доказывают смысловую верность операции.

## Атомарные страницы

В режиме `--map-mode atomic` (по умолчанию в CLI) у каждой атомарной страницы есть собственные границы. Цель — 40 000, жёсткая граница — 80 000; планируемый ответ — до 10 000. Подробности — [DIRECT-ATOMIC.md](DIRECT-ATOMIC.md).

- Считается полный запрос: system с методикой, JSON страницы и резерв единственного repair. Без токенизатора это байты UTF-8 — верхняя оценка, а не показания сервера. С `--business-tokenizer` используется локальный подсчёт.
- Перечисленные выше символьный предел и общий токенный предел (вход + максимальный ответ + оформление) продолжают действовать как защитные ограничения. Окно 1 млн не является целью заполнения страницы.
- Планируемый размер ответа нужен только для разбиения страниц. Ограничение вывода и резервы профиля модели он не меняет.
- Полный бизнес-текст, все контракты этапов и все факты идут в каждую страницу и не сокращаются.
