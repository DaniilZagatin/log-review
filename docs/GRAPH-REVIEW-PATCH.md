# R01: разбор всего репозитория по графу кода

`analyze` больше не отрезает код на 60 файлах / 120000 символах. Каждая строка выбранной области закрепляется ровно за одним интервалом. GLM получает интервалы ограниченными запросами, ответы проверяются кодом, затем находки сжимаются в ограниченную сводку для DeepSeek. Демонстрация `demo` осталась прежней строгой записью из четырёх ответов.

## Порядок запуска

На Windows замените `python3` на `py -3`. Каждый `--out` — новый каталог.

1. План без модели. Модельный клиент не создаётся, запросы не отправляются:

   ```bash
   python3 -B run.py analyze --repo /path/to/application --out runs/plan-01 --plan-only
   ```

   В выводе: число запросов GLM, их суммарный размер и полнота покрытия. В `code_review.json` — все интервалы, задачи, размеры и хеши запросов (без текстов промптов). Код 1 — часть строк или файлов не может быть передана.

2. Полный анализ с теми же параметрами области:

   ```bash
   python3 -B run.py analyze --repo /path/to/application --business-file /path/to/process.md --out runs/pilot-01
   ```

3. Продолжение после сбоя заданий или Ctrl+C — новый `--out`, старый каталог только читается:

   ```bash
   python3 -B run.py analyze --repo /path/to/application --business-file /path/to/process.md \
     --resume-from runs/pilot-01 --out runs/pilot-01b
   ```

   Повторно используются только ответы GLM, заново прошедшие проверку. Изменённые исходники, модель, промпт, guidance или параметры отклоняются до вызовов с указанием категории. Повреждённый ответ одного задания перезапускает только его. Бизнес-стадии выполняются заново.

4. Обратная связь: `python3 -B run.py feedback --run runs/pilot-01 --out feedback-pilot-01.zip`.

## Параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--review-request-chars` | 32000 | Максимальный размер system+user одного запроса GLM; исправления также проверяются по этому бюджету |
| `--review-workers` | 2 | Параллельные запросы GLM, 1–8 |
| `--max-followups` | 32 | Дополнительные чтения по запросам GLM, одно поколение |
| `--business-request-chars` | 240000 | Проверяемый до отправки размер бизнес-запроса, больше 1000; не подтверждённый контекст модели |
| `--max-files`, `--max-chars`, `--max-repo-bytes` | нет | Только остановка до вызовов, без обрезки |
| `--max-file-bytes` | 512000 | Больший файл — неподдерживаемый вход |
| `--allow-partial` | выкл. | Продолжить при неподдерживаемых файлах/строках; код выхода 1 |

Сбой HTTP или сети не повторяется автоматически; задание помечается, остальные продолжаются. Ответ GLM с неверной структурой, JSON или ссылками получает одну попытку исправления; в ней называется только категория ошибки. Ограничения по времени нет; Ctrl+C останавливает отправку новых заданий и сохраняет выполненные, а уже отправленный запрос может продолжиться на сервере.

## Что сохраняется

| Файл | Содержимое |
|---|---|
| `code_graph.json` | Объявления, вызовы-кандидаты, импорты, литералы. Это подсказки навигации, не доказательство выполнения |
| `code_review.json` | Для каждого интервала: передан ли текст, принят ли ответ, статус от GLM; задания, ошибки, дополнительные запросы и их статусы; все находки |
| `code_reduction.json` | Сводка для DeepSeek, полный каталог находок, дерево сжатия; `residual` — находки без пересечения диапазонов с основаниями карты, для дальнейшего сопоставления |
| `logging_inventory.json` | Полный инвентарь логирования без лимита мест и исключения области |
| `review/` | Контрольные точки для `--resume-from` |

`complete` в `code_review.json` означает: каждая строка передана, ответ принят и GLM отметил интервал как разобранный. Это не доказывает, что смысл понят верно. DeepSeek может ссылаться только на диапазоны, переданные ему в этом запросе. Неотражённые технические ветки остаются в `residual` и в открытых вопросах карты; они не обязательно бизнес-операции.

## Не проверено

Качество разбора на корпоративной репе, пропускная способность и окно контекста GLM/DeepSeek. Для большой репы сначала посмотрите число запросов в `--plan-only`.
