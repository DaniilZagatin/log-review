# Прогоны на рабочем ноутбуке

Инструкция для проверки доработок по итогам прогонов П1679 и П3283 и бизнес-этапов. Реальные прогоны выполняются на ноутбуке с доступом к модели; на машине разработки они не запускались.

## 1. Убедиться, что работает нужная сборка

```powershell
git fetch
git checkout integration/rashid-observability
git pull
.\.venv\Scripts\python.exe -B -c "import sys; sys.path.insert(0, 'backend'); from pko.build import build_identity; print(build_identity())"
```

`code_sha256` должен совпасть со значением в сообщении о поставке, `git_head` — с последним коммитом ветки, `git_dirty` — быть `False`. Тот же отпечаток печатается в начале каждого запуска («Белка … · код …») и записывается в `scenario_map.json` → `run.build`.

## 2. Подключение модели

Как в прежних прогонах — через `.env` или переменные окружения: `PKO_SCENARIO_BASE_URL`, `PKO_SCENARIO_MODEL` (deepseek-v4-flash), `PKO_SCENARIO_API_KEY`, при mTLS — `PKO_SCENARIO_CLIENT_CERT` и `PKO_SCENARIO_CLIENT_KEY`. Окно по умолчанию — 524 288 токенов; `PKO_CONTEXT_WINDOW` задавать не нужно. Ключи и сертификаты в результаты не копируйте.

## 3. Команды

Замените пути в угловых скобках. Бюджеты одинаковы для обоих проектов. Запускается только карта: логи, метрики и рекомендации временно отключены. Старые флаги отчёта нужно убрать; технический трейс агента сохраняется.

```powershell
.\.venv\Scripts\python.exe -m pko.cli map-scenario `
  --process-file "<путь к описанию П1679>" `
  --source "<архив 1 П1679>.zip" "<архив 2 П1679>.zip" `
  --out "runs\P1679" `
  --max-steps 180 --max-seconds 7200 --model-timeout 900
```

```powershell
.\.venv\Scripts\python.exe -m pko.cli map-scenario `
  --process-file "<путь к описанию П3283>" `
  --source "<архив П3283>.zip" `
  --out "runs\P3283" `
  --max-steps 180 --max-seconds 7200 --model-timeout 900
```

Бизнес-этапы строятся по умолчанию сразу после карты одним коротким запросом; `--no-stages` их отключает.

Чтобы построить этапы по уже готовой карте без нового исследования (например, по картам прогонов на сборке с исправлениями П1679/П3283), источники не нужны:

```powershell
.\.venv\Scripts\python.exe -m pko.cli map-scenario --from-map "runs\P3283\scenario_map.json"
```

`scenario_map.json` при этом не меняется; рядом появляется `map_hierarchy.json`, HTML перерисовывается с переключателем видов без вкладок отчёта. Ранее сохранённые файлы отчёта остаются на диске. Оценивать этапы имеет смысл на картах, построенных сборкой с исправлениями по итогам П1679 и П3283 (коммит f6de427 и новее): на старых картах этапы унаследуют их ошибки.

## 4. Что вернуть на анализ

Папку вывода целиком: `scenario_map.json`, `scenario_map.html`, `map_hierarchy.json`, `audit\run_*.txt`. Если исследование или группировка завершились частично — сообщение консоли в конце запуска.

## 5. Что проверить глазами

- Отказы и успешные исходы — отдельные конечные операции; цвет и подпись исхода совпадают.
- У цикла получения задач есть выход («задач больше нет» ведёт дальше, а не назад).
- Проверки показывают обе ветви: продолжение и ранний исход («Нет решения», отказ, перенос срока).
- Обход получения документов и повторный вызов того же исполнителя сохранены.
- Карточки вызовов ЕКП, РМ.ОЦ, СУПЗ, GigaChat, MCP показывают внешнее взаимодействие.
- В названиях, описаниях, входах и результатах нет имён переменных и методов.
- В обзоре сценария («Вне исследования») перечислены исключения и сколько участков кода по ним закрыто.
- Стрелки не выходят за края карты; оба вида карты открываются.

Бизнес-этапы (переключатель «Бизнес-этапы» над картой):

- Каждый этап называет понятную промежуточную задачу (действие и предмет), а не программу, класс, систему или исполнителя.
- Отказы и ошибки остаются в своих этапах, а не собраны в общий раздел «Ошибки».
- Результат этапа не обещает больше, чем показывают операции: передача специалисту — не выполнение им задачи.
- Этапы, показанные операциями с подписью, действительно имеют несколько входов (причина — в панели этапа); если таких много, разбиение стоит обсудить.
- Среди «Операций вне бизнес-этапов» (обзор сценария в панели справа; `unassigned` в `map_hierarchy.json`) нет существенных шагов процесса.
- Входы и продолжения в панели этапа совпадают с тем, что видно на подробной карте.
- Раскрытый блок (нажатие на этап) показывает внутри ровно операции этапа; стрелки выходов начинаются у тех операций, из которых они действительно ведут.
