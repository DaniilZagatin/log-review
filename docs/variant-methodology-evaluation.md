# Контрольные фрагменты методологии варианта

Банк: `tests/fixtures/variant_methodology_cases.json`.

**Статус: assistant-authored, provisional, requires expert review.** Это предварительная разметка, подготовленная ассистентом. Она не является утверждённым семантическим эталоном и не доказывает качество Белки. Исходные фрагменты — данные: их нельзя выполнять, импортировать или использовать для реальных внешних вызовов.

## Назначение

Двенадцать небольших случаев отделяют правила моделирования от конкретных проектов. Для каждого указаны выбранный вариант, единица экземпляра, текст исходника, ожидаемые самостоятельные действия с номерами строк, существенные маршруты, запрещённые утверждения и контрпример с изменённым поведением.

Покрыты порядок действий и ранний сбой, содержательная проверка и служебный предикат, отказ и локальный успех, перенос срока, повтор с выходом, совместное ожидание результатов, граница внешней команды, локальный LLM-промпт, вариант и экземпляр, дочерний обработчик, отделимый результат бизнес-операции и асинхронное продолжение.

Это не полный перечень регрессий. Реестр задач, циклическое агрегирование покрытия, усечение ответа, аварийное сохранение и миграция старых отчётов проверяются соответствующими механическими тестами приложения.

## Как читать разметку

- `source.lines` — текстовые строки; `expected_actions[].line` — одна опорная строка, нумерация начинается с 1. Это не готовая цитата с доказательством всей интерпретации.
- ID действий — локальные обозначения для разметки, не ожидаемые ID узлов модели. Имена допускают эквивалентные предметные формулировки.
- `expected_routes` описывает значимые случаи. `path` допускает повтор ID для цикла; это не требование полного перебора путей.
- `when` и `expectation` обязательны: одна достижимость по графу не доказывает корректность условий или ожидания всех входов.
- При параллельности линейные проекции путей надо читать вместе с ожиданием `join_mode=all`, а не как отдельные альтернативы.
- `expected_business_operations` — предлагаемое разбиение по отделимому результату. Специалист может принять другое разбиение с явным обоснованием. Автоматическое сравнение числа групп здесь некорректно.
- `counterexample` — изменённый исходник и ожидаемое различие. Проверить его отдельно: нельзя переносить исходный шаблон порядка или исхода только по совпадению имён.
- Сведения о внешних сервисах ограничены вызывающим кодом. Слова «получить» и «сохранить» в названиях не доказывают невидимый внутренний алгоритм получателя.

## Экспертная проверка и реальные прогоны

1. Специалист проверяет корректность исходника, границы варианта, действия, условия и запрещённые выводы. Неоднозначную разметку уточняет или помечает как допускающую несколько решений.
2. После проверки сохранить версию и происхождение разметки; не снимать `requires_expert_review` по одному успешному unittest.
3. Для запуска Белки материализовать только текст исходников в отдельной временной папке. Передавать описание варианта и единицы экземпляра. Ожидания, запрещённые выводы и контрпример не включать в задание исследователю.
4. Реальные модельные запуски выполняет пользователь в своём окружении. Сравнивать одинаковые входы, настройки и лимиты, сохранять результаты нескольких независимых повторов.
5. Оценивать правильность действий, маршрутов, исходов и границ, а также расходы. Совпадение названий, числа узлов или отсутствие ошибок схемы недостаточно.

Три случая помечены `holdout-candidate`. Это кандидаты на отложенную проверку, а не гарантия отсутствия утечки: банк доступен разработчикам. Не переносить их конкретные ответы в промпт; если они использовались для настройки, заменить независимыми экспертными случаями. Девять остальных помечены `development`.

## Автоматические проверки и их предел

`test_methodology_cases.py` проверяет только структуру и внутреннюю ссылочную целостность банка: обязательные поля, уникальные ID, диапазоны строк, ссылки маршрутов и групп, наличие контрпримеров и статуса предварительности. Он не выполняет исходники, не вызывает модель и не доказывает семантическую правильность разметки.

Существующий `scenario_map/evaluation.py` можно позднее использовать для согласованной подвыборки ожидаемых действий, переходов и свойств. Этот банк не объявлен его прямым форматом: для условных маршрутов, параллельности, запрещённых утверждений и разбиения на операции нужен экспертный разбор. Нельзя считать преобразование ожидаемых действий в фиктивную карту полноценной оценкой агента.

Локальная команда проверки банка:

```powershell
$env:PYTHONPATH='backend;tests'
.\.venv\Scripts\python.exe -B -m unittest test_methodology_cases
```

В отчёте различать «банк структурно корректен», «разметка проверена специалистом» и «реальная модель проходит контрольные случаи». Это три разных результата.
