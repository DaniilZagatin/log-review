# Граф функций для навигации

26 октября 2026. Codex и Claude обсудили предложение пользователя; независимый разбор Claude — `.local/claude-call-graph-discussion/answer.md`, сессия `8d5e2a17-75cb-4b7c-a667-ed3f6bda2733`. Это обсуждение архитектуры по локальному коду, без проверки актуальных внешних продуктов.

Решение: после текущего MVP добавить небольшой детерминированный индекс символов, импортов и мест вызова. Полный граф отдельным большим payload модели сейчас не нужен: выбранный снимок уже передаётся целиком. Реальная навигация требует ограниченного запроса соседних функций и чтения их текста.

## Где поможет

- Подбор небольшого снимка вокруг входной точки и логирования.
- Поиск обёрток между файлами.
- Конкретные сведения о вызванных символах за границей выбранного снимка.
- Позже — чтение вызывающих/вызываемых функций по вопросу модели.

## Ограничения

Статический вызов — синтаксический факт, а не выполненный маршрут. Переопределение имён, динамическая диспетчеризация, DI, декораторы, reflection и callbacks ограничивают разрешение целей. Не соединять функции только из-за одинаковых имён. Для same-file/import цели сохранять способ и границы разрешения; наличие импорта само по себе не доказывает неизменность привязки во время выполнения. Неоднозначные и внешние цели остаются такими. Очередь producer/consumer — отдельная предполагаемая связь по контракту/ключу, а не обычный вызов.

Технический граф не создаёт операций и переходов бизнес-карты. Требуемые бизнес-операции без кода сохраняются. Для каждого включённого файла нужны разрешённая область и замороженный текст с хешем. Индекс не даёт права молча читать соседние файлы вне пользовательского scope. Если их нет в снимке, показать внешнюю/неразрешённую цель и предложить расширить область.

## Минимальное продолжение

1. Python AST: объявления, импорты, места вызова, непосредственный владелец вложенного вызова, кандидат цели и статус разрешения. Повторно использовать уже имеющееся enclosing-symbol в logging inventory; не создавать ещё один независимый источник разметки.
2. Использовать индекс для обёрток, границ и выбора файлов; не включать его целиком в каждый prompt. Для других языков сначала проверить стек пилота и доступные инструменты; не выдавать совпадение строк за полноценное разрешение вызовов.
3. По измеренной необходимости — один раунд ограниченных запросов `symbol, direction, reason`, с лимитами числа чтений, строк и общего контекста. Результаты из того же снимка, с отдельным трейсовым событием.

## Проверка пользы

Шесть небольших репозиториев: вложенная функция; импорт с alias; два одинаковых имени метода; межфайловая log-wrapper; callback; очередь и обязательная бизнес-ветвь без кода. Сравнить текущий конвейер, индекс и индекс с ограниченным чтением соседей. Оценивать найденные нужные цитаты, ошибочные соединения, потерянные ветви и объём добавленного контекста. Прибавка числа узлов сама по себе не является улучшением.

Индекс и retrieval ещё не реализованы. Сначала требуется закончить и проверить сценарный HTML, затем получить первый запуск на корпоративной репе.
