# Интеграция актуальной Белки

В `src/pko` импортированы 102 отслеживаемых файла из `backend/pko` Белки на ревизии `9ccc1ed8c9e22ad4b59d952721f2ed7e17fe2c65`. Исходные SHA-256 записаны в `docs/belka-import.json`; это хеши импорта, а не утверждение об отсутствии последующих интеграционных изменений. Соседняя папка разработчика не требуется для запуска установленного продукта.

## Интеграционные изменения

- `pko.scenario_map.runner.run_scenario` принимает необязательный `prepared_workspace`. Без него работает исходное построение снимка; с ним использует уже допущенные неизменные тексты. Возобновление передаёт тот же аргумент через `resume_scenario` и штатную проверку checkpoint.
- `process_observability.map_input.snapshot_from_workspace` преобразует эти тексты в снимок Рашида без повторного обхода диска. Пути остаются `source-N/relative`; source roots задаются как `source-N=source-N`. Одинаковые имена в разных источниках не сливаются.
- Ревизия новой карты вычисляется единственной функцией `pko.stages.inputs.map_revision`, включая semantic_profile. Новая группировка проходит полный validator Белки. Карты без профиля читаются как прежние; неизвестный профиль отклоняется.
- Renderer полного продукта использует адаптер с вкладками и покрытием; его отдельное происхождение и правила обновления описаны в `src/process_observability/map_presentation/PROVENANCE.md`.

## Проверки происхождения

Снимок Белки сохраняет исходные переводы строк. Нельзя ослаблять проверку хешей read fragments для автоматического принятия CRLF/LF как одинаковых байтов: корректный файл метаданных обязан хешировать фактический снимок. В Windows fixture `test_map_first_guards` теперь явно записывает UTF-8 с LF, соответствующий его ожидаемому хешу.

Ключевые исходные тесты Белки и их fixtures находятся в `tests_belka`. Запуск из корня: `PYTHONPATH=src;tests_belka` и `python -X utf8 -B -m unittest test_scenario_schema test_methodology_hierarchy test_resume_runner`. Общий продукт отдельно проверяет межэтапные контракты в `tests/test_product_map_contract.py`.

## Обновление

Импортировать только отслеживаемый пакет новой ревизии, сверить исходные хеши, повторно применить перечисленные адаптации и прогнать проверки контрактов/renderer/возобновления. Не копировать окружение, ключи, локальные результаты и архивы. Изменения methodology или схемы требуют согласованного обновления consumer; совпадение номера schema само по себе недостаточно.
