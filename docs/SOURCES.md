# Источники и применимость

Машинный реестр находится в `materials/source-register.json`. Он содержит исходный путь, путь локальной копии, SHA-256, роль и статус материала.

| Группа | Статус и способ использования |
|---|---|
| Четыре полных HTML об этапах подготовки/данных/поставки/валидации | Предоставленные снимки внутренних инструкций. Использовать с указанием версии и границ полноты; актуальность live-систем не проверена |
| Пять HTML о каналах и логировании | Предоставленные снимки инструкций Logging, SMD, ClickStream, Kafka и общего порядка. Противоречия примеров и определений сохраняются как открытые решения |
| DOCX о требованиях к логам | **Предложение, не ground truth и не утверждённый контракт.** Использовать как источник кандидатов требований и словарей |
| Выбранные файлы PKO | Неизменённые снимки для точечного переноса, не целевое приложение и не доказательство пригодности реальных логов |
| Проверенные заметки Codex и рецензии | Производные выводы и рекомендации. Не могут повышать полномочия исходника или подменять отсутствующую методику |

Оригиналы и полные извлечения лежат в `materials/private/`, вне Git. Снимки PKO и компактные исследовательские заметки — в `references/`. Копирование не изменяет пользовательские исходники.

Известные открытые вопросы:

- Текущий официальный шаблон постановки процесса на учёт не предоставлен.
- Не выбран целевой процесс, приложение, стек и канал; доступность выбранного для пилота LLM endpoint ещё не проверена.
- Нет runtime-логов и подтверждения полноты их поставки.
- Не получены полные формулы части формальных метрик, источники стоимости/контактов/удовлетворённости и правила бизнес-календаря.
- Схемы и примеры предоставленных каналов местами расходятся по именам, типам, регистру и семантике. Агент должен сохранять исходное поле и явный маппинг, а не молча переписывать контракт.

Агент может продолжать подготовку черновика, показывая эти ограничения. Готовность пакета к формальной регистрации требует отдельной проверки по действующему шаблону и методикам.

## Последняя конфигурация моделей и TLS, 26 октября 2026

Пользователь задал GLM-5.3 на `tpgds-aihub0003:2720/v1` для кода и DeepSeek endpoint `dsv4flash-…/v1/chat/completions` для бизнес-смысла. Полные адреса — в `config/model.corporate.json`. DeepSeek model ID взят из `ai-agent-deepresearch/backend/src/config/settings.py:220`, базовый `thinking=false` — из `src/model_registry.py`. В проверенном `_build_openai_client` этого проекта явная передача CA/клиентской пары отсутствует; найденное применение `certs2` относится к OpenSearch. Мы не утверждаем, что воспроизвели несуществующее в этом коде подключение сертификатов DeepSeek.

По отдельной просьбе пользователя три файла из `ai-agent-deepresearch/certs/certss/certs2` побайтово перенесены в локальный `certs/deepseek`, исключены из Git и явно включены в частный ZIP. Для TLS используется HTTPS того же DeepSeek-хоста вместо исходного HTTP. Штатный Python SSLContext загружает CA и клиентскую пару, проверка сертификата/hostname включена. Подтверждена только локальная загрузка, не server handshake. Содержимое ключа в документацию/LLM не выводилось.
