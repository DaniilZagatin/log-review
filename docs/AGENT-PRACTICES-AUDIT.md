# Аудит агентского пайплайна по agents-best-practices

Дата: 30 октября 2026. Объект: полный продукт в `full-agent-test` после интеграции Белки и Рашида.

Применён навык `C:/Users/dan-z/.agents/skills/agents-best-practices/SKILL.md`, разделы agentic-loop, security-observability, workflow и границы проверки модельных предложений. Аудит проверяет конкретные инварианты исполнения; он не доказывает бизнес-полноту результатов модели.

## Архитектурные границы

Контроллер задаёт порядок этапов и общий бюджет. Белка предлагает карту через инструменты; код проверяет структуру и цитаты. Рашид анализирует логи относительно сохранённой карты. Метрики — предложения определений без наблюдаемых числовых значений. Все этапы используют один допущенный снимок исходников. Состояние попытки хранится вне диалога.

## Найденные и исправленные дефекты

| Дефект | Исправление | Проверка |
|---|---|---|
| Временный сбой сохранения мог стать обычной ошибкой модели, после которой работа продолжалась | Необратимая остановка RunBudget; RunHalt проходит сквозь вложенные обработчики модели до контроллера | Отказ диска до/после ответа; диск восстановился, но следующего запроса нет |
| Таймаут отдельных операций HTTP и ожидание HTTP429 могли превысить общий лимит времени | Общий async deadline на весь запрос, бюджетный sleeper для ожиданий | Отмена зависшего запроса; запрет ожидания за пределами бюджета |
| Resume принимал изменённую опубликованную карту | Проверка итоговых контрольных сумм, manifest, map_revision и хешей промежуточных артефактов до нового вызова модели | Изменение карты/контекста/manifest, неподписанный промежуточный файл, неподдерживаемый путь |
| Декларации внешних API логирования и --log-call терялись при resume | Нормализованный logging_contracts.json включён в пакет, настройки вызовов сохраняются в manifest и наследуются | Первый запуск с декларацией, продолжение без повторения флагов |
| Историческая отмена группировки повторно отменяла новую попытку | Старый сигнал не применяется как текущая отмена; при наличии checkpoint и модели возобновляется публикация/группировка принятой карты | Продолжение сохранённой карты с отменённой группировкой |
| Метрики могли принимать подменённую единицу счёта, лишние поля и изменённые блокеры | Строгий контракт, единица счёта принадлежит входу, блокеры вычисляет код, reasoning-теги отвергаются, публичный текст маскируется | Подмена полей/единицы/блокеров и близкие допустимые случаи |
| HTML мог объявить завершение при частичных данных, экспортировать приватные поля manifest | Проверка согласованности готовности и фильтрация публичной проекции | Partial-артефакт с completed manifest; приватные поля при экспорте |

Для каждого физического запроса сохраняются этап, время, хеш пакета, статус HTTP, длительность и числовой usage при наличии. Тексты промптов, credentials и скрытые рассуждения в общий журнал запросов не добавляются. Хеши обнаруживают изменение локальных артефактов, но не являются криптографическим доказательством их доверенного автора.

## Ограничения и оставшаяся приёмка

- Структурная проверка и синтетические ответы не заменяют живой ограниченный прогон и экспертную проверку смысла карты, привязок логов и метрик.
- При остановке внутри этапа принятый внутренний checkpoint может существовать раньше возвращённого публичного результата. HTML показывает опубликованные результаты; сохранённый префикс восстанавливается через resume.
- Незавершённые старые попытки без хешей артефактов не импортируются молча. Для них требуется новый запуск. Итоговые старые пакеты проверяются по доступным контрольным суммам; непроверяемые внутренние checkpoint-файлы требуют нового запуска.
- Общие лимиты — физические запросы и время. Денежная стоимость без заданных тарифов не вычисляется и не объявляется нулевой.
- После изменения источников или несовместимой конфигурации продолжение отказывается использовать прежнее исследование.

Основные regression-наборы: `test_product_audit_budget`, `test_product_resume_integrity`, `test_product_pipeline`, `test_product_metrics`, `test_product_report`, `test_product_belka_e2e`. Дополнительно запускаются полный офлайн-набор и ключевые исходные тесты Белки.

Результат проверок этого аудита: 657 офлайн-тестов продукта без ошибок (один пропуск из-за прав Windows на создание symlink) и 61 ключевой тест Белки — успешно. Модельные API и реальные бизнес-сценарии в ходе аудита не вызывались.
