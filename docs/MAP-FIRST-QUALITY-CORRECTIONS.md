### Объявленные контракты журналирования

Оператор может явно объявить назначение внешнего SDK: необязательный файл `logging_contracts.json` в каталоге `--artifacts` (по умолчанию рядом с картой):

```json
{"schema_version": "logging-contracts/1",
 "contracts": [{"callee": "Vendor.Sdk.info", "basis": "кто и на каком основании заявил, что это API журналирования"}]}
```

Имя/суффикс метода (`*Log`), configured `--log-call` и слово log в имени не являются доказательством. SHA-256 файла пишется в `SOURCE-ARTIFACTS.json`, контракты — в `logging_contracts` результата и в идентичность кэша. У подтверждённой цепочки всегда ограничения: реализация SDK вне репозитория, включённость уровня, исполнение и доставка статически не доказаны.

repair_details собирает независимые ошибки полей вместе: путь, код, допустимые ID, варианты SDK либо недостающие reads. Модель получает всё за единственный repair; число вызовов не увеличено. SYSTEM/profile/packet меняют fingerprint, старые checkpoint не переиспользуются под другим протоколом.
