# Проверка Белки на реальных исходниках после доработок устойчивости

Код и локальные тесты проверяются на ноутбуке разработки. Этот документ описывает отдельную проверку качества модели на ноутбуке с реальными данными. Синтетические тесты не доказывают полноту реальной карты.

## 1. Три свежих запуска

Использовать одну версию кода, один ZIP/каталог источников, неизменный текст описания и одни настройки модели. Сохранить текущие настройки подключения; не отправлять ключи и `.env` вместе с результатами. Для сравнения с v14 модель должна оставаться прежней; не менять её одновременно с обвязкой.

В PowerShell из корня проекта замените два пути на реальные:

```powershell
$processFile = 'D:\data\process.md'
$sourceZip = 'D:\data\source.zip'
1..3 | ForEach-Object {
    .\.venv\Scripts\pko.exe map-scenario --process-file $processFile --source $sourceZip --out "reports/real-stability/run-$_" --max-steps 300 --max-seconds 7200 --model-timeout 900 --summary-mode standard --summary-max-tokens 8192 --thinking
}
```

Запуски выполняются последовательно. Ненулевой код завершения/partial сохранить и разобрать, а не заменять только удачным результатом. Не запускать каждую попытку до получения красивой карты: нужны все три результата.

## 2. Продолжение после прерывания

Checkpoint предыдущей версии не является подходящей базой: меняются промпт и инструменты, совместимость проверяется строго. Сначала получить checkpoint новой версии.

Для отдельного опыта можно создать короткий запуск с `--max-steps 10 --no-stages` в отдельном каталоге. Это тест прерывания по бюджету, а не аварии сети. Скопировать его checkpoint в неизменный файл **до** возобновления. Из одной копии выполнить три продолжения, каждое в новую папку:

```powershell
$checkpointFile = 'D:\data\checkpoints\scenario_map.checkpoint.json'
1..3 | ForEach-Object {
    .\.venv\Scripts\pko.exe map-scenario --resume $checkpointFile --source $sourceZip --out "reports/real-stability/resume-$_" --max-steps 300 --max-seconds 7200 --model-timeout 900 --summary-mode standard --summary-max-tokens 8192 --thinking
}
```

Если исследование в checkpoint уже штатно завершено через finish, resume может продолжать только публикацию. Для проверки исследователя нужен прерванный запуск. После раннего checkpoint полезно повторить опыт с checkpoint, содержащим часть карты. Не нужно специально вызывать сетевой сбой.

## 3. Проверка группировки отдельно

Трижды сгруппировать один и тот же опубликованный JSON, не запуская исследование заново:

```powershell
$fixedMap = 'reports/real-stability/run-1/scenario_map.json'
1..3 | ForEach-Object {
    .\.venv\Scripts\pko.exe map-scenario --from-map $fixedMap --out "reports/real-stability/grouping-$_" --thinking
}
```

Группировка не должна переписывать исходную карту. Число групп само по себе не оценивает качество: проверять принадлежность действий и отделимый результат бизнес-операций.

## 4. Локальное сравнение

```powershell
.\.venv\Scripts\python.exe -B scripts/compare_scenario_runs.py reports/real-stability/run-1/scenario_map.json reports/real-stability/run-2/scenario_map.json --left-hierarchy reports/real-stability/run-1/map_hierarchy.json --right-hierarchy reports/real-stability/run-2/map_hierarchy.json --left-audit reports/real-stability/run-1/audit --right-audit reports/real-stability/run-2/audit --out reports/real-stability/comparison-1-2.json
```

Если группировка не сохранилась, убрать оба аргумента hierarchy. Различия формулировок ещё не означают ошибку. `unresolved_operations` требует ручного сопоставления: совпадение ID не считается доказательством, общая цитата нескольких действий не разрешает выбрать соответствие автоматически. Несовпадение снимков не сравнивается как одна версия процесса.

Для каждого опыта сохранить целиком папку результата: `scenario_map.json`, `scenario_map.html`, `map_hierarchy.json` при наличии, `scenario_map.checkpoint.json`, `audit/`. Не удалять неудачные попытки. Сводка сравнения дополняет оригинальные материалы, а не заменяет их.

## 5. Что оценивать в картах

- Одинаковый предмет экземпляра и границы процесса; пакет очереди не смешался с одной задачей.
- Сохранились проверки, вычисления, запросы, записи и внешние команды; они не спрятаны внутри общего узла.
- Тип предмета, отрицания и граничные условия не потеряны; отказная ветка не стала безусловной.
- Сохранились порядок, повторы, выходы и область обработки исключений.
- Запрос не объявлен доказанным бизнес-результатом; конечность/цвет обоснованы.
- В бизнес-операциях не появились новые маршруты, а группировка объясняется результатом.
- Повторные отклонения инструментов не занимают большую часть прогона; partial сообщает конкретную неполноту.

Повторить хотя бы свежие запуски на втором проекте. Для окончательной оценки нужен разбор специалистом спорных участков: три похожие карты могут одинаково ошибаться.
