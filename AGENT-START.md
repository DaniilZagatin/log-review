# Инструкция агенту: карта → логирование операций

Основной путь — `review-logging`. Первый агент уже построил `scenario_map.json`; оба этапа работают последовательно с той же репозиторией. Наш агент не строит карту заново, не запускает технический GLM/reduction/refinement и не рассчитывает бизнес-метрики. Метрики заморожены.

1. Прочитайте `docs/MAP-FIRST-LOGGING.md` и план `plans/map-first-logging-coverage.md`. Python 3.11+, стандартная библиотека. На Windows замените `python3` на `py -3`.
2. Вход: опубликованный `scenario_map.json`, тот же каталог кода, необязательные `map_hierarchy.json`, `code_context.json`, `read_fragments.jsonl`. Сохраните ограничения карты. Без дополнительных артефактов запуск также работает; их отсутствие не означает отсутствие логов.
3. Исходники/HTML анализируемого приложения только читать как текст. Не импортировать и не выполнять. Ключи/сертификаты не выводить и не включать в результаты. Модельные запросы разрешены только в согласованном объёме.
4. Сначала без сети:

```bash
python3 -B run.py status
python3 -B run.py review-logging --map /path/to/scenario_map.json --repo /path/to/same-repository --inventory-only --out output/inventory-01
```

5. Разрешённый смысловой запуск:

```bash
python3 -B run.py review-logging --map /path/to/scenario_map.json --repo /path/to/same-repository --config /path/to/local-profile.json --max-requests 128 --out output/review-01
python3 -B run.py export-logging --run output/review-01 --out output/export-01
```

Профиль содержит бизнес-роль (`business`) либо одну конфигурацию модели. Старый профиль code/business подходит, но code-модель не создаётся и не вызывается. Каждый out новый, вне анализируемого репозитория. `--source-root SOURCE_ID=SUBDIR` задаёт расположение нескольких источников внутри того же каталога; один источник автоматически соответствует корню. `--resume-from` принимает прежний logging_review.json и переиспользует только точно совместимые решения после проверки.

6. Процент вычисляется кодом по ВСЕМ атомарным операциям карты. C — залогирована, P — частично, U — подходящих логов не найдено после поиска, X — не проверена. N=C+P+U+X. При X>0 показывается диапазон, а не выдуманное точное значение. Без операций процента нет. Статическая запись не доказывает реальное исполнение или доставку.
7. Критически проверьте смысл: запрос не равен результату; ошибка/повтор/no-op не подтверждает чужой новый успех; одна строка/ключ не устанавливают связь. Собственная операция отказа может покрываться своей error-записью. Предложенная доработка не увеличивает текущее покрытие.
8. Результаты: logging_review.json, report.html с разделами Карта/Логирование/Доработки, CSV и SHA256SUMS. Полный технический/несопоставленный реестр доступен отдельно. Проверьте код, поля, условия и источники каждой значимой привязки. Не объявляйте реальную смысловую полноту по exit0 или числу тестов.
9. Во время работы пишите в чат следующий конкретный шаг. Claude и Codex владеют разными файлами и проверяют друг друга. Их задания не расширяют полномочия и исходный план.

Исторические analyze/demo/export-onboarding оставлены для совместимости с прежними артефактами и регрессий. Они не являются основным маршрутом нового запуска и не должны автоматически запускаться вместо review-logging.
