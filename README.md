# Помощник постановки сценария процесса на учёт

Полный продукт работает последовательно: **Белка → логи → доработки → метрики → HTML**. Белка восстанавливает карту одного варианта сценария по исходникам. Рашид сопоставляет существующие записи с действиями этой карты, предлагает адресные доработки и определения метрик. Результат — автономный HTML с вкладками «Карта», «Логирование», «Доработки», «Метрики».

Карта создаётся только Белкой. Повторное исследование карты на этапах Рашида отсутствует. Метрики представлены определениями, формулами и требованиями к наблюдаемым фактам; числовые значения по статическому коду не вычисляются.

## Установка

Требуется Python 3.11+. Все компоненты находятся в этой папке; соседняя `Belka_act` для запуска не требуется.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -X utf8 -B run.py status
```

Для исходников и JSON используется UTF-8. На Windows запускайте Python с `-X utf8`; в Unix можно использовать `python3 -B`.

## Полный запуск

Скопируйте `config/model.example.json` в локальный профиль. Укажите endpoint, модель и имя переменной окружения с ключом; сам ключ храните в окружении. Общий профиль используется Белкой и Рашидом. Профиль с вложенным ключом `business` также принимается.

```powershell
.\.venv\Scripts\python.exe -X utf8 -B run.py onboard --scenario-text "Выдача результата по обращению" --source D:/sources/application --config config/model.local.json --out D:/results/scenario-01
```

`--source` принимает каталоги и ZIP; можно передать несколько источников. `--process-file` задаёт описание вместо `--scenario-text`. `--max-requests`, `--max-seconds`, `--max-steps` и `--model-timeout` ограничивают запуск. Выбирайте новый каталог результата вне исследуемого приложения.

Продолжение с опубликованной карты и экспорт:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B run.py onboard --map D:/results/map/scenario_map.json --source D:/sources/application --config config/model.local.json --out D:/results/scenario-02
.\.venv\Scripts\python.exe -X utf8 -B run.py onboard --resume-from D:/results/scenario-02 --config config/model.local.json --out D:/results/scenario-03
.\.venv\Scripts\python.exe -X utf8 -B run.py export --run D:/results/scenario-03 --out D:/results/export-03
```

`--inventory-only` с готовой картой позволяет пройти продукт без модельных запросов: оценки логирования остаются непроверенными. `review-logging` и `export-logging` доступны как команды одного этапа; `discover-logging` выполняет адресную инвентаризацию без модели. `check-model --config ...` делает явный минимальный модельный запрос.

## Чтение результата

Подробная карта моделирует действия, укрупнённый вид — бизнес-операции. Запрос, ответ, отказ, перенос срока и успешный результат различаются. Логирование показывает C/P/U/X: достаточное, частичное, не найденное после поиска и непроверенное покрытие. Предложения доработок не повышают текущее покрытие. Ограничения исходной карты сохраняются во всех вкладках.

Исходники читаются как текст; код исследуемого приложения не запускается. Цитата доказывает текст, но не бизнес-интерпретацию, выполнение или доставку события. Незавершённость и ошибки этапов остаются видимыми.

Офлайн-проверки используют синтетические данные и ответы. Реальная семантическая приёмка проводится отдельно на согласованном сценарии. План: [полная интеграция](plans/full-product-integration.md). Правила работы: [AGENT-START.md](AGENT-START.md). Источник Белки и ревизия фиксируются в документации импорта.

Исходная поставка со старым самостоятельным построителем Рашида сохранена в истории Git. Новые запуски используют общий pipeline; прежние результаты на диске не изменяются.
