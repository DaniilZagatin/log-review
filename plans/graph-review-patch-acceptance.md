# Приёмка R01

26 октября 2026. R01 реализован Claude, проверен Codex и прошёл отдельное чтение интеграции Claude. Это приёмка локального продукта на искусственных входах; корпоративные модели и реальная репа не запускались.

## Результат

- Обычный `analyze` читает всю допустимую выбранную область, строит технический граф и план ограниченных запросов GLM, проверяет ответы, выполняет одно поколение дополнительных чтений и агрегирует находки для DeepSeek.
- `--plan-only` работает без конфигурации/клиентов модели. `--resume-from` читает старый запуск и сохраняет результат в новый; изменённые зависимости отвергаются, повреждённый ответ пересчитывается отдельно.
- Бизнес-модель может ссылаться только на реально переданные ей диапазоны. Полный каталог и не сопоставленные с картой находки сохраняются. Статический граф и отметки модели не доказывают исполнение или смысловую полноту.
- Изменения HTML, сценариев, палитры, названий колонок и карточек формул включены. Блокеры и состояния JSON сохранены, наблюдаемые численные показатели по коду не создаются.

## Ревью и исправления

Claude выполнил отдельное read-only ревью замороженной копии интеграции, сессия `3cf78763-10d3-4484-9add-e82ebb3d557c`. Существенных проблем в границах ссылок, resume, повторах транспорта и прерывании не выявлено. Исправлены два подтверждённых небольших дефекта: корреляция запросов агрегации с API-ответами и раннее отклонение бюджета бизнеса ≤1000. Для обоих есть проверки. Старый тест передачи описания П3283 переведён на новый протокол технического ответа; проверка полного текста и хеша сохранена.

Ревью не включало документацию и прогон тестов. Codex отдельно проверил команды и поправил устаревшие описания роли guidance и JSON repair. После замораживания копии в workflow добавлена только явная отметка частичного scope; последующие коррекции Codex ограничены указанными двумя дефектами и точностью текста открытых вопросов. Диапазоны без пересечения не названы доказанно отсутствующими в бизнес-карте.

Полный JSON/контракт/range repair допускается один раз. Если исправленный запрос не помещается, задача явно завершается с причиной; бюджет не превышается. Ошибки HTTP/сети автоматически не повторяются.
