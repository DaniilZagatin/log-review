# Проверка плана R01

26 октября 2026. План написал Claude Opus в read-only запуске `.local/claude-graph-review-plan`; сессия `8d5e2a17-75cb-4b7c-a667-ed3f6bda2733`. Codex проверил его по текущим `source_tools.py`, `workflow.py`, `cli.py`, `log_discovery.py`, `tracing.py`, `review_reduction.py` и тестам. При подготовке плана проектные файлы не изменились. До реализации нового пути проходят 178 прежних offline-тестов; это не проверка R01.

Решение: принять план к исполнению с обязательными уточнениями ниже. Они приоритетнее спорных предложений исходного плана.

1. **Ссылки бизнес-модели.** Полный реестр исходных находок хранится, но `semantic_ranges` не расширяется до диапазонов, которые бизнес-модель не получила. В каждом запросе перечисляются реально переданные refs. Пропущенные refs остаются доступными в полном каталоге и учитываются в остатке; дополнительное чтение допустимо только через типизированный ограниченный запрос. Редкая ветка, не отражённая картой, должна оставаться явно видимой. Наличие child ID в сводке не доказывает сохранение её смысла.
2. **Импорты и неоднозначности.** Нельзя разрешать импорт по произвольному суффиксу пути. Использовать точный путь пакета в корне или явно определённом source root; неоднозначные roots, re-export, shadowing/rebinding и динамика остаются кандидатами/unknown. `self.method` — лексический кандидат, а не доказательство runtime-диспетчеризации. Совпадение literal/topic не создаёт ребро вызова или доставку.
3. **Повторы запросов.** Один repair допустим только для отклонённой структуры/диапазонов ответа. Ошибка транспорта/HTTP сохраняется как неуспешное задание без автоматического повтора. Возобновление явно запускает оставшиеся задания. Не подменять провайдер и не вводить дедлайны.
4. **Контексты и неполнота.** Лимит измеряется по точному отправленному system+user. Полный inventory/unknowns/evidence не копируется молча в каждый запрос. Любой отбор имеет счётчик/причину и полный локальный оригинал. Бизнес-бюджет настраивается и не считается проверенным context window модели. Неполный scope и сбой конкретной стадии различаются; выход CLI 1 сообщает незавершённый охват. Не объявлять семантическую полноту по одному факту передачи текста.
5. **Параллельность и прерывание.** Потоки выполняют только модельный вызов; координатор валидирует, сохраняет checkpoints и ledger. Для поздних API-событий после Ctrl+C нужен закрываемый trace и блокировка. Не использовать ожидающий завершения `ThreadPoolExecutor` как обещание немедленной отмены. Удалённый запрос может продолжиться после локального выхода.
6. **Совместимость демонстрации.** Предпочтительно сохранить существующий fingerprint-bound demo без изменения запросов и его четырёх ответов. Новый путь проверяется отдельными scripted fixtures и CLI transport mocks. Если replay всё же изменится, это должно быть явным и проверенным; нельзя заменять его неконтролируемым fake fallback. Базовые тесты адаптируются только при реальном изменении контракта.
7. **Проверки.** Несколько файлов в одном небольшом задании допустимы. Проверять отсутствие исходников вне явно переданных owned/context intervals, а не требовать один файл в каждом запросе. Cross-file wrapper должен приводить к реальному дополнительному чтению по графу. Каждая строка учтена, включая module-level statements, декораторы и oversized segments; цитаты не могут пересекать несмежные интервалы.
8. **Поставка.** Нужен полный пользовательский путь через `analyze`, не только библиотечные S1–S3. Основа патча — архив SHA-256 `deb153d1c80b5d390094005912210af13336701647e77440b0d37810f7e388cc`. Не менять существующий ZIP 0.1.0. В патч не включать `certs/`, `inputs/`, `config/`, реальные материалы, `.local/` и payload прогонов. Applier проверяет все pre-images до изменений и не пишет при несовпадении. Обязательна проверка на чистой распаковке.

Исполнение делегируется Claude по срезам S1–S5, затем упаковщик/инструкция S6. Codex независимо читает изменения, запускает offline-проверки и проверяет готовый патч. Реальное качество на корпоративной репе и доступность корпоративных моделей остаются непроверенными.
