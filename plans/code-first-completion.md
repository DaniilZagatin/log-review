## C1 — Черновик пакета процесса из уже полученных результатов

**Зависимости:** принятый R01; существующие контракты карты, необходимых фактов, предложений по логированию и метрик. **Цель:** аналитик и разработчик могут забрать согласованный набор материалов из одного запуска без ручного копирования HTML.

**Реализация:** небольшой детерминированный экспорт существующего bundle. Никаких дополнительных модельных вызовов, повторного чтения целевой репы или исполнения SQL/Python модели. Состав: описание и границы процесса, карта/сценарии и ссылки на отчёт, словарь найденных и предлагаемых бизнес-событий с различимым происхождением, case/join-правила только при наличии в результатах, доработки логирования, определения метрик с формулами и зависимостями, источники и открытые вопросы. CSV предназначены для просмотра; JSON сохраняет полные структуры и идентификаторы. Не восстанавливать отсутствующие поля догадками и не выдавать черновик за официальный шаблон.

**Файлы:** новый модуль экспорта, его отдельные тесты; CLI только точечное подключение новой локальной команды; инструкция пилота. Перед записью выбрать окончательные имена по текущему коду. Экспорт использует собственный новый каталог; исходный запуск и target приложение остаются неизменными.

**Инварианты:** IDs/refs совпадают с bundle; required/implemented не схлопываются; предлагаемые события отличаются от найденных; нет численных результатов процесса без наблюдений; JSON/CSV/Markdown не теряют обязательный этап из-за отсутствия кода. CSV не запускает формулы при открытии в таблицах. Невалидный или неполный bundle проверяется и обозначается, а не выглядит готовым пакетом.

**Выход:** команда экспорта на синтетическом завершённом и частичном прогоне, проверка ссылок/полей/экранирования, отсутствие новых модельных вызовов и изменений исходного запуска. **Откат:** отключить команду; JSON/HTML исходного анализа остаются пригодными.

## C2 — Приёмка текущего входа и прозрачный остаток исходного плана

**Зависимости:** C1, принятый R01. **Реализация:** сопоставить E01–E21 исходного плана с существующими тестами; добавить только содержательные отсутствующие сценарии, относящиеся к текущему входу по исходникам. Не считать synthetic replay оценкой качества живой модели. Отдельно перечислить проверки, которым нужны фактические записи/история/внешние справочники.

Обязательны: требуемая операция без кода остаётся видимой; upstream/To Be не повышается до факта реализации; proposal не создаёт принятого обязательства; старые якоря/кеш после изменения входа отвергаются; неполный scope и сбой стадии различаются; выдуманная ссылка/непереданный ref отвергается; статический вызов не доказывает commit/доставку/полноту; модель не публикует выдуманные числа процесса; секреты и инструкции в исходнике не обходят границы. Проверки связывать с конкретными ожиданиями, а не новым числом тестов ради отчёта.

**Файлы:** отдельные acceptance-тесты/искусственные fixtures при необходимости, документ матрицы проверки. **Выход:** точные прошедшие/неподдерживаемые/отложенные проверки с основаниями. **Откат:** сохранить выявленный regression-case и ограничить неисправную функцию, не удалять сценарий ради зелёного результата.

## C3 — Закрытие документации и передача пилота

**Зависимости:** C1/C2. Убрать устаревшие текущие утверждения о границах и статусе R01, сохранив историю проверок как историю. Показать один актуальный путь: проверка модели → plan-only → analyze → resume при необходимости → экспорт → feedback. Инструкции для OpenCode должны читать полное описание выбранного процесса и не подменять модель демонстрацией. Никакой установки каналов сбора как предварительного условия.

**Выход:** воспроизводимая офлайн-инструкция на поставляемом дереве; новые материалы входят в отдельную проверенную поставку. Закрывать шаги только после независимой проверки Codex.
