# Некритичная ошибка ссылки на методику

Основание: пользователь попросил сначала один понятный retry, затем игнорировать невалидные поля вместо остановки всего результата. Конкретный дефект run15: название пакета `process-observability` попало в `guidance_ids`; единственный repair получил HTTP429.

## Объём и зависимости

Зависимость: принятый R06/A1–A3. Файлы: `workflow.py`, `test_workflow.py`, эта запись и локальные свидетельства `.local/auxiliary-guidance-01/`. R06 ZIP и прежние прогоны неизменны.

1. Первый ответ проверяется строго. Ошибка получает существующий единственный repair с путём поля, правилом и допустимыми ID.
2. Если repair не дал принятого ответа, последний действительно полученный JSON можно проверить локально ещё раз, без API. Невалидные элементы `guidance_ids` исключаются; неверный тип/отсутствие этого вспомогательного поля означает пустой список, а не придуманное обоснование. Неверный необязательный `cards[].ref` становится null: карточка явно получает `location_unresolved`, без source_anchor и evidence_ids. Каждая такая коррекция вызывает полную проверку заново и возможна не более одного раза на карточку.
3. Все остальные поля, обязательные данные и источники карты, идентификаторы, зависимости и контракты проверяются заново без послабления. Никакого общего исправления JSON или fuzzy matching. Непроверенная ссылка никогда не становится проверенной: она отсутствует с явной причиной.
4. Сохраняются оба реальных исхода запросов, хеш/номер исходного ответа, отдельный исход локальной проверки и предупреждения с точными путями. Пустая атрибуция помечается `not_established`. Исходный ответ не переписывается; его версия в итоговом результате содержит только допустимые ссылки на правила.

## Критерии выхода

Регрессии: лишний ID вместе с допустимым; отсутствие/неверный тип/пустой список; ошибка транспорта на repair; применение к карте/карточкам/метрикам; неподтверждённый nullable адрес карточки становится unresolved; обязательные источники карты, действия, fact ID и обязательные поля продолжают блокировать стадию. Нужны focused/full offline, неизменный строгий demo/export и production-path проверка настоящего технического кеша перед новым живым бизнес-прогоном.

Это не подтверждает смысл рекомендаций модели. Живой результат принимается отдельно.
