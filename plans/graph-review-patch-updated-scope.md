Операции выбранного сценария поднимаются внутри своих этапов; стрелки привязаны к перемещённым узлам. При «Все сценарии» возвращается полное расположение, уникальные ветви имеют цвет кнопки, общие участки нейтральны.
2. Бледный зелёный/оранжевый показывают привязку к коду и найденным событиям. Не заявлять runtime-полноту из статического вызова. Отсутствующая привязка — серый пунктир, не доказанное отсутствие реализации.
3. Колонки Тип/Извлечение в таблице логирования скрыты. Термин «инструментирование» заменён в интерфейсе на «Доработки логирования»; JSON protocol не переименовывать.
4. HTML/Markdown карточек метрик показывает формулу, определения переменных, нужные факты/события, заполненные правила. Численные результаты, readiness, сообщения «не рассчитано» и пустые поля периода скрыты; исходные состояния/значения сохраняются в JSON.
5. Полный набор 21 поля и категории значимых событий из SRC-004 теперь передаются на map/coverage через общий FACT-SOURCE-CATALOG независимо от выбора Kafka/СМД. Не превращать их в единую обязательную raw-схему.
6. Пять направлений КГБ, известные определения и сверка 5% из HTML добавлены в metrics guidance. Отдельная официальная методика по ссылке ещё не предоставлена.
7. Пользователь разрешил пока самостоятельно определить формулы из доступных полей. `metric-formulas.md` содержит предложенные формулы объёма, исходов, ошибок, длительности, повторов, первого прохода, исполнителей/передач. Детали — `docs/METRIC-CATALOG.md`, проверенные первичные web-источники от 26.10.2026. Агент выбирает подходящие и привязывает к конкретным операциям/полям. Это рабочие определения, не банковский норматив. Трудозатраты/стоимость/CSAT/SLA не выводить из отсутствующих данных.

## Интеграция

- Не подключать весь бизнес-скилл к новому GLM worker вместе с legacy CODE_SYSTEM: старый response schema несовместим с S2, а полный system может не оставить 4000 source chars при default32k. Нужен отдельный компактный TASK: code system для нового reply contract; для технического контекста можно явно отобрать FACT-SOURCE-CATALOG/LIFECYCLE. Полный бизнес-скилл остаётся у DeepSeek. Реальный sys+user измеряется до каждого вызова.
- Корреляция API-трейса использует SHA256(system+'\n'+user); S2 request hash использует canonical JSON пары. Привести их к одному формату или явно сохранить оба с разными именами. Не менять fingerprint-bound runtime replay на permissive fallback.
- Guidance расширен по поручению пользователя. У синтетического replay обновлены только ключи запросов; тела четырёх ответов сохранены байт-в-байт после canonical serialization. Локальная проверка `.local/r01-demo-fingerprint-migration.json` подтверждает hash каталога ответов. Новый mock/review CLI проверяется отдельно; live не использует demo fallback.
- Патч обязан включить изменённые guidance/code/tests/docs и контролируемую миграцию replay. Allowlist release_patch.py расширен точечно; config/certs/inputs по-прежнему исключены.
